# Лабораторная работа №5

- **Цель работы**: разработка базового SPA на React.
- **Порядок показа**: скриншоты 1–3 — страницы фронтенда с mock и вкладкой Network; скриншоты 4–5 — реализация изображения по умолчанию; скриншоты 6–7 — код компонентов для фильтрации, передаваемые props; скриншоты 8–9 — все используемые хуки.
- **Контрольные вопросы**: React, props и состояние, компонент и элемент, `useState` и `useEffect`, жизненный цикл компонента, Vite и Babel.
- **Задание**: разработать страницы фронтенда приложения на React и TypeScript

Базовый интерфейс приложения **«Кислоты и реакции»** для гостя аналогичен двум страницам лабораторной работы №1 — **лента** и **плитка**. Содержимое карточек получается только из коллекции mock-объектов (`src/modules/mock.ts`), без подключения к бэкенду. Вёрстка выполнена компонентами React-Bootstrap (`Navbar`, `Nav`, `Card`, `Card.Img`, `Card.Body`, `Spinner`). На странице плитки реализован **фильтр по молярной массе** (двойной ползунок «от–до»).

Стек: React 18, TypeScript, Vite, React-Bootstrap, react-router-dom. Redux и Context API не используются (по условию).

```shell
npm install
npm run dev   # http://localhost:3000
```

## Нижняя навигационная панель

Панель закреплена внизу экрана «телефона» (375×812, стиль iPhone с Dynamic Island) и не прокручивается вместе с контентом. В неё входят **четыре пункта**, доступны только два:

| Пункт | Иконка | Доступен | Поведение |
|-------|--------|----------|-----------|
| **Лента** | ☰ | да | переход на `/`; подсвечивается, когда страница открыта |
| **Добавление** | ＋ | нет | серая неактивная кнопка (`disabled`), страница в этой лабораторной не реализуется |
| **Плитка** | ▦ | да | переход на `/tiles`; подсвечивается, когда страница открыта |
| **Вход** | 👤 | нет | серая неактивная кнопка (`disabled`), авторизация не реализуется |

## Страница «Лента» — `/`

Полноэкранная карточка реакции в формате TikTok: видео на весь фон, текст и панель действий поверх него.

**Кнопки и поля:**

- **Иконка «Лайк»** `❤` — количество лайков реакции (`reaction.likes`); для гостя только отображение, кликабельной не является;
- **Кнопка «Далее»** (`→`) — показывает следующую реакцию из mock-коллекции, список зациклен;
- **Заголовок** — кислота с формулой, например «Соляная кислота (HCl)» (`reaction.acid_name`, `reaction.acid_formula`);
- **Описание** (`reaction.description`) — по умолчанию показываются **2 строки** (CSS `line-clamp: 2`); клик по тексту раскрывает описание целиком, повторный клик сворачивает обратно;
- **Чипы «М.м.» и «Конц.»** — молярная масса в г/моль (`reaction.molar_mass`) и концентрация в % (`reaction.concentration`) на полупрозрачной подложке.

Если у реакции нет видео, подставляется `/DefaultVideo.mp4`, постером служит `image_url` или `/DefaultImage.png`.

## Страница «Плитка» — `/tiles`

Каталог реакций сеткой 2 колонки (по 2 карточки в ряду).

**Кнопки и поля:**

- **Заголовок** — «Каталог реакций»;
- **Фильтр по молярной массе** — двойной ползунок (`DualRangeSlider`) с диапазоном 0–200 г/моль и подписью текущего интервала «Молярная масса: от X до Y г/моль»; фильтрация пересчитывается через `useMemo`;
- **Карточка реакции** (компонент `ReactionCard`):
  - изображение — при пустом `image_url` подставляется `/DefaultImage.png`;
  - название кислоты (`reaction.acid_name`);
  - молярная масса и концентрация (`М.м.: … г/моль`, `Конц.: … %`);
  - количество лайков (иконка сердца);
- **Клик по карточке** — открывает эту реакцию на странице «Лента» (`/?id=N`);
- Если под фильтр ничего не подошло — сообщение «Ничего не найдено :(».

## Используемые хуки

- **`useState`** — индекс текущей реакции и раскрытость описания (`FeedPage`, `FeedItem`); текущий диапазон фильтра (`TilesPage`);
- **`useEffect`** — загрузка mock-коллекции при монтировании; переход к реакции с `?id=` при изменении адреса (`FeedPage`);
- **`useMemo`** — вычисление списка реакций, отфильтрованного по молярной массе (`TilesPage`);
- **`useSearchParams`** — читает `id` из адреса `/?id=N` и открывает нужную реакцию в ленте (`FeedPage`);
- **`useNavigate`** — переход с «Плитки» на «Ленту» по клику по карточке (`TilesPage`), переключение пунктов navbar (`AppLayout`);
- **`useLocation`** — подсветка активного пункта navbar по текущему пути (`AppLayout`);
- **`useOutletContext`** — передача общего списка карточек между layout и страницами через `Outlet` (механизм react-router, не Context API).

### Передаваемые props

Пример для скриншотов 6–7 — фильтр. `TilesPage` хранит состояние диапазона и передаёт
его в компонент ползунка вместе с функцией обратного вызова, сам компонент состояния
не имеет (управляемый):

```tsx
<DualRangeSlider
  min={MIN_MASS}
  max={MAX_MASS}
  value={massRange}
  onChange={setMassRange}
/>
```

```tsx
interface Props {
  min: number;
  max: number;
  step?: number;
  value: [number, number];              // текущий диапазон [от, до]
  onChange: (value: [number, number]) => void;
}
```

# Расчёт аппаратных требований

## Исходные данные

- Пользователей системы: **127**
- Услуг (просмотренных реакций) на пользователя в день: **5**
- HTTP-запросов на одну услугу: **4** (загрузка списка — 1, карточка/деталь — 1, изображение — 1, видео-превью — 1)
- Рабочее время пользователей: с 8:00 до 24:00 = **16 часов = 57 600 с**

## 1. Расчёт RPS

```
RPS_сред = пользователи × услуги_в_день × запросов_на_услугу / рабочее_время_с
RPS_сред = 127 × 5 × 4 / 57600 = 2540 / 57600 ≈ 0,044 запр/с
```

Пиковая нагрузка (коэффициент неравномерности 5, вечерние часы):

```
RPS_пик = 0,044 × 5 ≈ 0,22 ≈ 0,25 запр/с
```

## 2. Расчёт числа ядер и ОП

Допущение: 1 ядро CPU обрабатывает **20 RPS** для данного приложения (статика + API).

```
Ядра = RPS_пик / 20 = 0,25 / 20 = 0,0125 → округляем вверх с запасом = 1 ядро на приложение
```

Итого сервер: 2 ядра (1 — приложение, 1 — СУБД/кэш), ОП — **по 4 ГБ на ядро**:

```
ОП = 2 ядра × 4 ГБ = 8 ГБ
```

**Требуемая ВМ: 2 ядра CPU, 8 ГБ ОП.**

## 3. Прирост БД за 5 лет

### Таблица услуг (реакций) — размер одной записи

| Поле | Тип | Размер |
|------|-----|--------|
| id | bigint | 8 Б |
| reaction_name | varchar(100) | ~80 Б |
| acid_name | varchar(50) | ~30 Б |
| acid_formula | varchar(20) | ~12 Б |
| molar_mass | double | 8 Б |
| concentration | double | 8 Б |
| calcium_carbonate_mass | double | 8 Б |
| description | text | ~500 Б |
| status | varchar(20) | ~15 Б |
| image_url | varchar(200) | ~120 Б |
| video_url | varchar(200) | ~120 Б |
| likes | int | 4 Б |
| created_at | timestamp | 8 Б |
| **Итого** (с индексами) | | **~1000 Б ≈ 1 КБ** |

Новые услуги добавляются со скоростью **20 услуг/день**:

```
Записей за 5 лет = 20 × 365 × 5 = 36 500
Объём таблицы услуг = 36 500 × 1 КБ ≈ 36,5 МБ
```

### Объекты в S3 (изображения и видео услуг)

Изображение — **300 КБ**, видео — **5 МБ** на услугу:

```
Объём S3 = 36 500 × (0,3 МБ + 5 МБ) = 36 500 × 5,3 МБ ≈ 193 450 МБ ≈ 193 ГБ
```

### Итоговый размер диска

```
Диск = БД (36,5 МБ) + S3 (193 ГБ) + ОС и ПО (20 ГБ) + запас 20%
     = (193 + 20) × 1,2 ≈ 256 ГБ → берём 300 ГБ SSD
```
